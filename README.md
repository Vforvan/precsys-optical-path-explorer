# precsys-optical-path-explorer

[![在线演示](https://img.shields.io/badge/在线演示-打开页面-2ea44f?style=flat-square)](https://vforvan.github.io/precsys-optical-path-explorer/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg?style=flat-square)](LICENSE)

SCANLAB **precSYS** 五轴（X / Y / Z / α / β）激光微加工扫描头的**教学型三维光路交互模型**。

**在线访问：<https://vforvan.github.io/precsys-optical-path-explorer/>** —— 用手机、平板或电脑浏览器打开即可，无需安装任何东西。
（也可以离线使用：`npm run build` 产出的单个 `dist/index.html` 双击就能跑，见第 2 节。）

> 这是一个**教学型工程示意模型**，不是对 precSYS 实机的拆机复刻、CAD 逆向或加工仿真器。
> 内部光路采用公开专利和官方资料建立的教学型等效模型。模块功能和光学关系可信，
> 具体封装、尺寸及部分 Z 轴结构不代表生产设备内部实物。

---

## 1. 它能让你在 5～10 分钟里看懂什么

- precSYS 的"五轴"为什么不是五根机床直线轴，而是**五个高速光学伺服轴**；
- 振镜电机 / 转轴 / 反射镜 / 数字编码器如何组成**闭环光学轴**；
- 镜片只转很小角度，反射光方向为什么变化约**两倍**角度；
- X、Y 振镜如何让**焦点在工件平面移动**；
- α、β 模块如何让输出光束**保持平行但产生横向位移**；
- 光束偏心进入物镜后，为什么**焦点基本不动、入射方向却变了**；
- Z 轴如何通过改变**物镜前光束的会聚状态**移动焦点；
- 为什么 Z 模块的折返镜**没有自己的执行轴、却每帧都在转**（随动解算）；
- 为什么真实机械角常常小到肉眼看不出来，以及页面用什么方式把它显示出来；
- 为什么五个执行轴**必须联合标定**，而不是一轴对应一个坐标；
- 进动钻孔时**哪些镜片在动**、哪些部件没有旋转；
- 直壁 / 正锥 / 负锥分别对应怎样的焦点轨迹与入射角策略。

### 在线版与发布方式

本仓库用 **GitHub Pages** 发布在线版，发布源是 `main` 分支的 `/docs` 目录：

- `docs/` 是**构建产物**，由 `npm run build` 自动从 `dist/` 同步而来，请勿手工编辑；
- 它随源码一起提交，因此线上页面和仓库内容永远对得上；
- 改完代码后，`npm run build` → `git add` → `git commit` → `git push`，Pages 会自动重新发布。

> `dist/` 与 `docs/` 内容相同，区别是 `dist/` 不入库（见 `.gitignore`），`docs/` 入库。
> 为什么不直接让 Pages 指向 `dist/`：Pages 只能发布仓库里**已提交**的目录。

### 怎么打开（重要）

**双击 `dist/index.html` 即可**。构建脚本会把 JS 与 CSS 全部内联进这一个 HTML 文件，
并打成经典脚本（IIFE），所以离线双击就能运行 —— 整个模型就是一个可以随便转发的 HTML 文件。

> 为什么必须内联：浏览器在 `file://` 下会以 CORS 拒绝**外链** module 脚本与带 `crossorigin`
> 的样式表（origin 为 `null`），普通 Vite 产物双击打开时只有 HTML 骨架、三维部分根本不启动。
> 因此 `npm run build` 默认走单文件模式；`npm run build:split` 保留传统分离产物，供本地服务器使用。

**不要双击源码目录根下的 `index.html`**：那是 Vite 的开发入口，引用的是 `src/main.ts`，
浏览器无法执行 TypeScript。若误点，页面会显示一段说明告诉你该怎么做（不会白屏）。
开发时请用 `npm run dev`。

离线可用：`three` 已被打包进 `dist/index.html`，页面运行时不请求任何外部资源。

## 4. 光学模型是怎么算的

所有光线都由 **起点 + 单位方向**表示，每一次反射都由镜面法向算出：

```
d_reflected = d − 2·(d·n)·n
```

没有任何"手工摆放"的假光路：镜片姿态、光束折线、焦点位置、读数面板上的每个数字，
都来自同一条链路：

```
用户命令 (X, Y, Z, α, β)
  → educationalInverseModel() 或 naiveInverse()   ← 解出五个执行轴
  → traceTrain()（逐面反射追迹）
  → 入瞳状态 (h, u, v, 半径, 会聚度)
  → 焦点状态 (X, Y, Z, AOI, 光锥角)
```

### 4.1 与公开数值自洽的物镜等效模型

公开值：物镜焦距 75 mm、**有效焦距 25 mm**、典型入射光束直径 2 mm、典型全会聚角 0.08 rad。模型后段传播距离取 75 mm，不代表确认实机工作距离。

本模型把物镜等效为"内部扩束 M=3 + 焦距 75 mm 聚焦镜"，于是四个公开值互相自洽：

| 关系 | 结果 |
|---|---|
| 2 mm 光束扩到 6 mm，聚焦到 75 mm | 半角 atan(3/75) = 0.04 rad → 全角 **0.08 rad** ✓ |
| 有效焦距 = 1 / 0.04 | **25 mm** ✓ |
| 焦点位置 | `X = 25 mm × u`（u = 入瞳处主光线坡度） |
| 入射角 | `AOI = atan(−h / 25 mm)`（h = 入瞳处主光线相对光轴的高度） |

515 min. focus 版本（入射光束 2.5 mm）自动得到 0.1 rad 全角，与规格表一致 —— 见 `src/tests/objective.test.ts`。

### 4.1.1 怎么确认"光线与镜面的关系是对的"

画面上每个反射点都会画出三样东西（"显示 → 镜面法线"开关控制）：

- 黄色小球：光线与镜面的**实际命中点**（直接取自追迹结果）；
- **青色短线**：该点的**镜面法线（垂线）**，长度 16 mm；
- 白色横线：镜面内的切向，与法线垂直，用来确认镜面朝向。

入射光与反射光关于这条青色法线对称，这就是模型的全部依据 `d′ = d − 2(d·n)n`。
点击任意一块镜片，右侧信息卡会给出**当前光线的实测入射角与偏转角**（2×入射角），
它和画面上的法线是同一份数据，不存在"画一套、算一套"。

想快速核对 45° 折叠关系，可用正视视角（相机沿 +Y 方向、与振镜等高）：
45° 镜在正视图中呈现为标准斜线，竖直入射与水平出射严格关于镜面对称。
`node tools/closeups.mjs` 会生成 `screenshots/cu-front-*.png` 这组检查图。

### 4.1.2 渲染上踩过的坑

- **"机器中间有一块黑墙把整机截断"**：那是被写错的地面。
  本项目 **Z 轴是竖直方向**（工件表面 z = 0、扫描头在上方），而 `PlaneGeometry` 默认就躺在
  XY 平面、法向 +Z —— 这已经是一块合格的水平地面，**不需要旋转**。
  早期照搬"Y 向上"的习惯写了 `plane.rotation.x = Math.PI / 2`，
  结果把 900 mm × 900 mm 的地面转成了一面**竖直墙**，正好穿过机器中轴（y = 0）：
  默认视角在墙的一侧，于是"只能看一半机器"；视角跨过 y = 0，墙跑到身后，整机就出现了。
  修法就是删掉那行旋转（见 `create-scene.ts → addGround`）。
- **雾也会"吃掉"半个机器**：原来有 `Fog(900, 2400)`，相机离得远时远端部件会淡入背景色。
  现在直接不使用雾。
- three.js 里 **metalness 接近 1 的材质如果没有环境贴图会渲染成纯黑**：
  早期镜片 metalness 0.95 又没有 `scene.environment`，所以"看不清每个镜片"。
  现在用 `PMREMGenerator + RoomEnvironment` 生成环境贴图，金属才真正呈现为镜面。
- 光束画得太粗太亮会盖住镜片：现在中心光线半径增益降到 0.9、包络降到 1.6，
  并把振镜电机从 6.5 mm 半径缩到 2.8 mm，让镜面成为视觉主体。
- 每块镜片都单独克隆材质并加一圈高亮轮廓（`EdgesGeometry`），
  这样"高亮某个轴、其余降透明度"不会互相干扰，镜片边界也始终清晰。
- 物镜原来是两段饱和紫蓝色的空心大圆筒，看起来像"悬在光路上的胶囊"；
  现在改为中性玻璃灰蓝的三段镜筒 + 金属加强环 + 内部镜组 + 出光口。
- **Z 模块两块镜片粘在一起（穿模）**：折转镜与折返镜的落差原来只有 16 mm，
  而两片 20 mm 的 45° 镜片各自的 Z 向半投影约 14 mm，屏幕上看就是两块镜片互相穿插。
  现在落差取 34 mm，并加了 `geometry-overlap.test.ts` 用 OBB 判定做回归保护。
- **随动折返镜"凭空自己动"**：它没有执行轴却每帧在转，因为法向是解出来的。
  现在为它补了一台电机，读数用本帧解出的法向求带符号角（见 4.3）。
- 排查这类"有东西挡住画面"的问题时，可以用 `node tools/diagnose-occlusion.mjs`：
  它会拍默认视角、逐个隐藏分组（`window.__PRECSYS__.groups`）各拍一张，便于按排除法定位。

### 4.2 α/β 平行移束模块

依据专利 **EP3932609B1**（Claim 1/3/4/5、[0015][0030][0032]）：

- 三面平面镜：一面可转（26，振镜驱动）+ 两面固定（28、30），三镜法向共面；
- 光束反射 **四次**，第 1 次与第 4 次都落在可转镜上；
- 数学结论：出射方向 `φ_out = φ_in + 2(θ₂₈ − θ₃₀)`，**与可转镜转角 θ₂₆ 无关**。
  所以可动镜转动只让出射光束**横向平移**，方向不变 —— 即专利所说的
  "parallel offsetting the laser beam relative to an optical axis"。

本模型的实现细节（`src/optics/parallel-shift-module.ts` 与 `src/tests/parallel-shift.test.ts`）：

- 两块固定镜法向相同 → 输出方向与输入**严格平行**（测试断言偏差 < 1e-9 度，全行程成立）；
- 可动镜机械角 ±3.5° 对应约 ±7 mm 移束行程，灵敏度约 2 mm/度；
- 专利未规定单镜 26 的具体结构。模型自定**同一振镜支架上的两块平行镜面 + 法向台阶**，
  只能演示功能，不能证明已复原专利单镜，更不能推断实机必有背面入射或开孔。
- F1→F2 段现在按有限光束、旋转局部轴、斜入射足迹、板厚及安全余量校验。
  典型光束通过不代表宽光束在全行程通过，失败会在侧栏显式告警。

### 4.3 Z 动态调焦等效模块

公开资料没有给出 precSYS Z 轴的完整生产结构。[0043] 举例轴向移动光学元件，
权利要求 6 未将此机制规定为唯一实现。本模型采用反射式教学功能等效，不据此推断实机 Z 轴类型：

- 可动折转镜受执行器驱动真实偏转，光线按反射定律逐面计算；
- 折返镜法向每帧由"入射方向 → 目标方向 −Z"解出，输出严格沿 −Z；
- 变焦反射镜曲率随执行器信号在**凸—平—凹**之间变化，直接实现"改变物镜前光束会聚度"，
  输出会聚度 = 2·cos(入射角)/R；
- ±1 mm 焦点范围只需约 ±0.8° 执行器角。

**关于折返镜的"随动"**：折返镜没有自己的执行轴，它的法向是每帧被解出来的，
因此页面给它单独画了一台电机，读数用**本帧解出的法向相对名义法向的带符号角**
（不能用执行器角驱动，否则显示出来的角度是错的）。这也是页面上会出现
**6 个驱动外形**的原因：5 个模型执行轴 + 1 个 Z 随动示意件；不是 precSYS 第六轴或第六台电机的公开证据。

**关于角度指示弧（×12）**：Z 轴走完 ±1 mm 全程只需要约 ±0.8°，
转子上的键位在这个量级下肉眼等同静止。因此每台电机额外画一段
**放大 12 倍显示**的指示弧，方向与转向一致，标签上标注 `×12`。
它只是读数指示，**不参与任何光学计算**，镜片姿态与光线仍按真实角度计算。

页面固定显示：

> 此处为动态调焦功能等效模型，展示"改变物镜前光束会聚状态 → 改变焦点 Z"的关系，
> 不代表 precSYS 内部真实镜组排布。

### 4.4 为什么必须联合标定

模型里存在两类由所选教学几何计算得到的耦合，不代表实机的结构或标定值：

1. **Y 振镜不在等效入瞳参考位置**（两片振镜相距 16 mm，是本模型选取），
   所以 Y 扫描移动焦点的同时会把一部分 Y 向偏心带进入瞳 → 不需要的入射角分量；
2. **Z 执行器改变光束在折返镜上的落点**，使下行光束整体横移 → 同样变成入瞳偏心。

`naiveInverse()`（一轴对应一坐标）忽略这些耦合，残差可达几度；
`educationalInverseModel()` 用有限差分求出 5×5 耦合矩阵并做牛顿迭代，
把 (X, Y, Z, α, β) 同时解到位（残差 < 0.01）。页面上的"联合补偿"开关就是这两者的切换。

**注意**：`educationalInverseModel()` 是等效逆映射，**不是** SCANLAB 控制器算法，
也不代表实机标定矩阵。

## 5. 事实边界

页面用三种色标区分每一条信息：

| 色标 | 含义 | 例子 |
|---|---|---|
| 绿 · 公开确认 | 官方手册 / 知识库可查 | 五轴工厂标定坐标、AOI ±7.5°、Z ±1 mm、进动 ≤650 Hz、入射净孔径 4 mm、物镜焦距 75 mm 与有效焦距 25 mm、保护玻璃与气体喷嘴 |
| 紫 · 专利原理 | EP3932609B1 明文的功能结构 | 权利要求 1 的两套平行移束单元（26→28→30→26 四次反射、首末同一可动镜）、二维偏转功能（权利要求 2）、分光监测（权利要求 8/9） |
| 橙 · 教学等效 | 为讲清原理而建立的等效模型 | 可动镜的分体镜面与法向台阶、转轴取向、XZ/YZ 光路平面、镜间距与口径、X/Y 振镜排布与通道映射、Z 模块光焦度与随动件、物镜内部镜组与后段传播距离 |

**关键区分：专利原理 ≠ 实机装配图。** 专利给出的是功能与权利边界，
不是尺寸、位置、转轴或空间排布。因此本轮把下面这些**从"公开确认/专利原理"下调为"教学等效"**：

- X 振镜与 Y 振镜的位置、转轴、折向 +X 的排布，以及"X 振镜 = 入瞳平面"的说法
  （改为"以 X 镜命中点作**等效入瞳参考**"，倾斜镜面不等于水平入瞳面）；
- 监测分光元件的取样位置与传感器排布（分光监测功能本身有公开依据）；
- 平行移束模块内部结构：单镜 26 的分体台阶替代、转轴、尺寸、XZ/YZ 排布；
- 物镜内部镜组与"后段传播距离 = 工作距离 75 mm"的表述
  （公开的是**焦距** 75 mm 与有效焦距 25 mm，工作距离未公开）；
- Z 随动折返镜（**没有独立自由度，不是实机第六轴**，电机外形仅为示意）。

**AOI 的口径**：`AOI = atan(−h/Feff)` 中的 `h` 是相对**机器光轴**的入瞳偏心，
AOI 是相对传播参考轴 **−Z** 的有符号角分量。工件水平时参考轴与表面法线平行；
工件倾斜需另算光线与表面法线夹角。专利 Fig.3 的 α/β 表示的是出光倾角与工件入射角，
**不是**本页的 X/Y 分量，本页换算公式专利未给出。

**不做的事**：不把教学模型标成"precSYS 内部真实 CAD"；不虚构镜片型号、材料、镀膜、尺寸与公差；
不根据外壳照片猜测内部镜片位置；不把网页计算结果当作真实加工参数或安全边界；
不宣称网页做了衍射、像差、热漂移或材料去除的精确仿真；
不用"中心光线能解出"冒充"有限光束能安全通过"（见下）。

**几何校验**（侧栏"事实边界 / 几何校验"卡片）：

- 只校验 α/β 的 F1→F2 段对两可动镜片的**包络避让**，计入 1/e² 光束包络、
  斜入射足迹、2.6 mm 板厚投影与 0.25 mm 安全余量；
- 零位缝宽 57.12 mm 沿镜面 u 轴测量，**与 11 mm 法向台阶不是同一个量**；
- 典型半径 1–1.25 mm 在 ±3.5° 全行程余量为正；半径 3 mm 在 +3.5° 时
  保守余量 −2.04 mm，卡片转为**红色告警**；
- 这是局部避让校验，**不是整机无碰撞认证**，也不保证高斯光束尾部零截光。

**视觉放大**（页面右上角常驻显示）：

- 光路轴向长度按教学需要拉开，**非等比例**（实机主体参考包络约 303.5 mm × 271 mm）；
- 焦点 Z 位移放大 ×6（公开范围仅 ±1 mm，等比绘制肉眼不可见）；
- 光束会聚度放大 ×60；
- 电机转角指示弧放大 ×12（真实机械角常只有零点几度，不放大等同静止）；
- 进动动画是慢动作：650 Hz 的真实一圈约 1.5 ms，浏览器帧率不是真实控制周期。

## 8. 测试覆盖（`npm test`，85 个用例 / 10 个文件）

- 反射方向与法向定向无关、镜面转 δ 反射光变化 2δ、光线-平面求交；
- α/β 模块：四次反射落点、首末命中同一可动镜组、**输出方向偏差 < 1e-9 度**、
  位移单调、二分法换算机械角、中心光线不穿任何一块镜片、两固定镜分居两侧；
- **包络避让（`parallel-shift`）**：零位缝宽 = 51√2 + 11 − 26 = **57.12 mm**（不是 11 mm 台阶）；
  两个模块在 ±3.5° 全机械行程、半径 1 / 1.25 / 3 / 5 mm 下逐点校验余量
  （含斜入射足迹、2.6 mm 板厚投影、0.25 mm 安全余量）；
  典型光束（≤1.25 mm）余量正、超宽光束如实返回负余量并判失败；
  转动后用旋转后的局部坐标，入射会聚度参与半径计算；
- 物镜：三个型号的光锥角都与公开规格一致、`X = 25u`、`AOI = atan(−h/25)`、
  Z 会聚度与 ±1 mm 可逆；
- 全链路：零位焦点在原点、光路顺序正确、X 振镜不引入偏心、
  Y 振镜与 Z 执行器的耦合确实存在、±7.5° AOI 与 ±1 mm 焦点都在行程内可达、
  补偿开启后六组工况残差 < 0.01；
- **专利事实边界（`patent-boundaries`）**：α/β 转轴正交、
  零位进出口同向 −Z、α 偏心反号 / β 偏心同号、AOI 参考机器 −Z 轴、
  宽光束与追迹失败都必须显示几何告警（不能"求解成功"覆盖），
  以及自定镜面与模块必须标"教学等效"、不得冒充"公开确认"；
- 几何互不穿插（`geometry-overlap`）：用 OBB 判定同模块内各镜片在零位与
  两个极端执行器状态下都不相交，并对 Z 模块镜间距的最小值做断言 ——
  这条是为"折转镜与折返镜穿模"回归加的；
- 加工：四种模式行为、进动相位锁定、倾斜幅值、螺距推进、慢放换算。

## 9. 已知的未知（页面"结构依据"模式内也列出）

- 可动镜的具体形式（专利附图把可转镜画成一条实心镜条，未说明两次反射如何避开镜片；
  本页的分体镜面只是教学替代，**不能据此推断实机是分体、背面入射或开孔**）；
- Z 轴内部镜组排布与曲率；专利 [0043] 另举"轴向移动光学元件/组件"的实现，
  权利要求 6 未把机制限定为唯一形式，**不能断言实机 Z 轴不是振镜、也不能断言就是振镜**；
- 两套平行移束单元的光路平面是否互相垂直（专利只写两个位移方向"可选正交"；
  本页选取 XZ/YZ 正交平面，输出高度 470/330 mm，**不是两个 z = 常数的平行平面**）；
- 可动镜的转轴取向（本页选取垂直于单元光路平面，专利未规定）；
- 物镜内部镜组数量、口径与镀膜；真实工作距离（公开的 75 mm 是**焦距**，不是工作距离）；
- 位移量—转角关系式（专利 [0016] 只有"每转角位移量与镜间距有关"的定性表述，无公式）；
- 实机五个控制通道与模型五个执行轴的编号对应关系；
- 控制器内部的真实标定矩阵、查找表与伺服参数。
